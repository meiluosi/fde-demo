# 三轴状态与建议结论

## 三轴状态规则

对**技术可行、价值判断、信任与权限**分别判定。引用记录 ID，ID 来自[记录表](../templates/session-log.md)。

| 状态 | 条件 |
|---|---|
| 已验证 | 至少 2 条符合该轴要求的独立记录；没有未解决的反向信号；数字带样本数与分母 |
| 部分 | 至少 1 条记录，类型为行为、承诺、具体言语或技术观测之一 |
| 未验证 | 没有可引用记录，或只有泛泛言语、解读、用户转述 |
| 被推翻 | 至少 1 条直接反证，类型为行为、承诺或技术观测 |

各轴“已验证”可计入的记录类型：

| 轴 | 可计入类型 |
|---|---|
| 技术可行 | 技术观测、行为 |
| 价值判断 | 行为、承诺 |
| 信任与权限 | 行为、承诺 |

“已验证”的范围始终限于所写的样本、场景与观众。小样本的“已验证”只表示机制成立，不代表总体。

## 建议结论

| 结论 | 条件 | 必须同时写 |
|---|---|---|
| Proceed | 价值与信任均为已验证，技术为已验证或部分，且无被推翻的轴 | 试点范围建议：对象、边界、仍未验证的假设；不是上线授权 |
| Iterate | 方向未被推翻，但至少一轴不足 | 补验证：补哪一轴、怎么补；下一轮改什么 |
| Pivot | 主张、场景或用户被推翻，出现了更值得做的发现 | 转向：新的主张或场景及其依据；被推翻的内容如何留底 |
| Stop-Defer | 缺少继续的条件（无人愿意用、拿不到数据或授权、风险过高） | 重开条件：什么变化出现后再评估 |

`scripts/check_debrief.py` 会检查上述条件，违反时报错。这是规则检查，不是业务审批。结论属于建议，最终由客户业务负责人作出。

## 不要这样判断

- 不因客户客气、领导满意、掌声而 Proceed。
- 不因一次现场失败而 Stop。先看失败是否被分类、是否在预期内、客户如何反应。
- 不把“未验证”写成“被推翻”。没证据支持不等于有证据反对。
- 不用 Demo 的小样本推算总体收益。
- 不把 Proceed 写成上线授权。
- 不把 ask 获批简单当作项目获批。权限是信任的证据，项目是否推进由业务负责人决定。
